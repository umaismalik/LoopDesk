# LoopDesk | Team & Project Management

LoopDesk is a multi-organization workspace for projects, team collaboration, client ticket requests, meetings, notes, and task tracking. The product name and logo are provisional branding; verify domain and trademark availability before a commercial launch.

## Meeting notes and voice transcription

The Meetings and Meeting Notes areas are scoped to the selected project. Meetings can be in person or online using Google Meet or Zoom, with a maximum scheduled duration of 60 minutes. A project admin can connect Google Calendar from the meeting form; when connected, scheduling a Google Meet creates a Calendar event with a shareable Meet URL and includes that URL in project invitation emails. To enable it, enable the Google Calendar API in Google Cloud, configure an OAuth consent screen and OAuth client, add the callback URL `https://YOUR_APP_HOST/api/google-meet?action=callback` as an authorized redirect URI, and set server-side `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`. Set `APP_URL` to the canonical site origin so the redirect URI matches (for local development, use the local app origin). The OAuth client needs `openid`, `email`, and `https://www.googleapis.com/auth/calendar.events` scopes. Keep the client secret stable: the app uses it to encrypt the stored refresh token. Zoom remains available by opening Zoom and pasting its invite link manually. Recording requests microphone permission only and records the selected device microphone without browser noise/echo processing; it cannot capture remote-call audio directly unless the microphone can hear the speakers. Multiple clips can be recorded in one unsaved recording set and saved together as one monthly project note with combined transcript, generic key points, member-specific notes, editable action items, and each clip's audio. Use **Cancel recording notes** to discard the unsaved set. A set supports up to 20 clips. Audio/transcript capture and transcription require explicit user interaction; saved recordings are uploaded to the app's configured storage. Each audio clip is limited to 4 MB when using remote Supabase storage and 25 MB with local file storage; if an upload fails, the note remains saved and the upload can be retried. Local filesystem storage is not durable on ephemeral hosting such as Vercel, so configure persistent storage before relying on deployment for data retention.

Voice transcription uses the multilingual Whisper Base model with q4 quantization on WebGPU when available and WASM/CPU otherwise; Urdu/Urdu-English mode uses Whisper Small. Audio is translated into English and split into 30-second chunks with overlap to reduce short-chunk context loss. Suspicious repeated output from Whisper Base triggers a retry with Whisper Small. Placeholder/low-information output (for example, a "foreign language" marker) is retried using a more careful decode and rejected with a clear error if still unusable. Small may take longer and downloads the larger model on first use. Select Urdu for Urdu or Urdu-English mixed speech; auto-detection and English are also available. A transcript editor appears after transcription so you can correct recognition mistakes; generated key points and member cards update from the corrected text. No automatic speech recognizer can guarantee 100% accuracy, so verify names and action items before emailing. The app uses the active project team roster and common pronunciation/spelling aliases for Sami, Irfan, Zunaira, Mashal, Haider Ali, Umais, Adil, and Mashhood to suggest individual summary cards when a member's name and a clear turn-taking phrase such as "your turn", "tell me about your task", or the Roman Urdu "aap apne task ke bare mein batao" are recognized. Matching tolerates a one-character spelling difference and common Soundex-like name variants; when a match is ambiguous, it avoids guessing. This is a text heuristic, not voice identification or speaker diarization. Each recording card can be reviewed and shared by email directly to its identified member; unreviewed transcripts and action items are never emailed automatically. Meeting summaries and saved recordings remain in the browser until explicitly saved. No Cloudflare account, API token, or paid transcription service is required. The open-source inference runtime is loaded from jsDelivr and model files download from Hugging Face on first use; both require an internet connection. The browser caches model files for later use. Transcription runs in the browser; when the user explicitly saves a clip as a note, its audio and resulting transcript/notes are uploaded to the app's configured storage.

Voice recording supports pause/resume and multiple clips in one monthly recording note. Finishing a clip translates the speech; select **Record another clip** to continue without saving or cancelling. Save all transcribed clips together with **Save recording as note**, or discard the unsaved set with **Cancel recording notes**. Transcription requests are serialized and duplicate development-mode requests for the same clip share one transcription job. Each clip can be played back to confirm the microphone captured it clearly; a failed transcription can be retried without recording again.

Data storage: when a real `SUPABASE_URL` and `SUPABASE_SERVICE_KEY` are set, the portal stores its database and uploaded files in Supabase (free tier), which is what makes Vercel hosting possible. If the URL is still `your-project.supabase.co`, the app uses local file storage in `data/db.json` and `data/uploads`; no Supabase setup is needed for local development. To enable Supabase later, use the actual project URL from Supabase **Project Settings → API**, then run `supabase.sql` once and `node --env-file=.env.local scripts/migrate-to-supabase.js` to move existing local data.

## Team task cards, reports, and reminders

Open **Meetings**, select a meeting, and use the member cards to review recent ticket work, record a previous-task update, and add each member's next actions with a priority. **Save notes** creates/updates the corresponding entry in **Meeting Notes**, assigns each action, and emails the member. In Meeting Notes, task details and priority are already populated; set or adjust the deadline there. Deadlines include a time and are stored as UTC instants while the browser displays local time. Reports export an Excel-compatible UTF-8 CSV filtered by month or week and optionally by a team member.

Meeting-task reminder checks send emails approximately 24 hours, 12 hours, 2 hours, and 5 minutes before the deadline. The 5-minute reminder is checked in a one-minute window, and sent reminders are recorded per task so they are not repeated. Vercel Hobby cannot run the required every-minute cron, so use the free Cloudflare Worker in `cloudflare/reminder-cron.js` with a `* * * * *` Cron Trigger. Set the Worker variables `APP_URL` (the deployed app URL) and `CRON_SECRET` (matching the app server secret); the Worker calls the protected `/api/cron` endpoint once a minute. On non-Vercel Node.js deployments, the in-process reminder checker runs every minute while the server is running. Set an assigned task's date and time in Meeting Notes; for example, set the due time to 4:20 PM to expect the reminder at about 4:15 PM. Email provider credentials must be configured on the app server.

## Free pilot deployment (Vercel + Supabase + Cloudflare)

This is a low-cost pilot setup, not a guaranteed production service. Vercel Hobby is restricted to personal, non-commercial use; do not use it to sell or commercially operate this multi-company portal unless your use is permitted by Vercel's current terms. Supabase Free projects may pause after seven days of inactivity, have no downloadable database backups, and have limited database/storage quotas. Cloudflare Workers Free has request/CPU quotas. Check each provider's current terms and limits before launch.

1. Push this repository to GitHub. Do not commit `.env.local`, `.env`, or any service keys.
2. Create a Supabase project. In **SQL Editor**, run the contents of `supabase.sql`. From **Project Settings → API**, copy the Project URL and the `service_role`/secret key; keep the key private.
3. If you want to move local data and uploaded recordings, first put the Supabase URL and secret key in your local `.env.local`, then run `node --env-file=.env.local scripts/migrate-to-supabase.js` from the repository root. Back up `data` before migrating.
4. Import the GitHub repository into Vercel and deploy it. In **Project → Settings → Environment Variables**, add `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `CRON_SECRET`, `APP_URL`, `RESEND_KEY`, and `RESEND_FROMEMAIL`. Generate `CRON_SECRET` with `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`. Set `APP_URL` to the deployed site's `https://...vercel.app` origin. Create a Resend API key and verify the sender domain in Resend before using team emails. Redeploy after adding the variables.
5. In Cloudflare, open **Workers & Pages → Create application → Create Worker → Edit code**. Replace the starter code with the contents of `cloudflare/reminder-cron.js` and deploy. Open the Worker **Settings → Variables and Secrets** and add `APP_URL` (same Vercel origin) and `CRON_SECRET` (exactly the same value configured in Vercel; mark it as a secret). Under **Settings → Triggers → Cron Triggers**, add `* * * * *`.
6. In Vercel, confirm `CRON_SECRET` and `APP_URL` are set for Production and redeploy if changed. In Cloudflare Worker **Logs**, confirm “Reminder check completed”. Create a task assigned to an active member, set its deadline 6 minutes ahead, and check that member's email and spam folder about 5 minutes before the deadline. Email delivery and exact timing depend on the providers.

## Email delivery

All application emails (project invitations, password resets, meeting invitations and participant summaries, ticket notifications, and deadline reminders) use Resend when `RESEND_KEY` and a verified-domain `RESEND_FROMEMAIL` are configured on the server. For a simple domain-free setup, configure Gmail SMTP: when `SMTP_HOST=smtp.gmail.com`, the app uses Gmail directly and does not require Resend domain verification. Use a Google App Password (not the normal account password; enable 2-Step Verification first), `SMTP_PORT=465` or `587`, `SMTP_USER` (the full Gmail address), `SMTP_PASS` (the 16-character App Password; spaces are removed automatically), and `SMTP_FROM` (a sender matching that Gmail account). A Gmail authentication error means the App Password or account settings need correction. With other SMTP hosts, a failed Resend send falls back to SMTP and reports both provider errors if delivery still fails. Keep provider credentials in server environment variables only; never expose them to client-side code or commit them. Restart the app after changing environment variables. Email APIs report provider errors for invitation and meeting sends; deadline reminder failures are logged and are not marked as sent so they can be retried.

## Companies and meeting edit permissions

The workspace supports multiple companies, each with multiple projects. Projects retain separate team membership and project-scoped tickets, meetings, notes, tasks, files, and reports. Existing company and project names are retained; a fresh installation starts with a "My Company" organization. Project admins can add projects to companies they administer and create a new company; members only see projects they belong to.

Only project Admins and Collaborators can edit all meeting cards, saved meeting notes, and task details. Other team members can update the status of tasks assigned to them (Open, In Progress, or Completed). They can request temporary meeting edit access; a project admin may approve or deny the request. An approval grants access only to that member's own meeting card and assigned tasks for one hour, then expires automatically. Shared meeting notes, recordings, other members' cards/tasks, task reassignment, and shared-note creation remain restricted.

Temporary edit requests are listed on the Admin dashboard and emailed to active Admins in the project. Email delivery depends on the configured email provider; the dashboard remains the in-app approval inbox if email is unavailable.

In Meeting Notes, member-specific updates and action items are grouped into collapsible sections by team member to keep long meeting histories manageable.

Voice capture routes an update to a clearly mentioned team-member name; if no name is spoken, it uses the card selected before recording. Selecting a card without recording or entering notes does not create or alter any content.
